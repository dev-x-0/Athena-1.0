## 1. Executive Findings

Athena’s underlying backend engine (`app.py` and `athena.db`) currently executes deterministic performance tracking, basic trend extrapolation, and automated alert generation. Based on code and database analysis, the research findings are as follows:

* **Current Analytical Scope**: Athena tracks performance across 6 campaigns and 6 SKUs across channels including Meta, Google Shopping, TikTok, and Direct.
* **Forecasting Mechanics**: The current forecasting logic in `/api/insights` applies Ordinary Least Squares (OLS) linear trend regression over a 30-day daily revenue series (`window("30d")`) to project the next 7 days of top-line revenue.
* **Budget Optimization Mechanics**: The `/api/optimize` decision function reallocates up to $30\%$ (`cut_share = 0.30`) of spend away from campaigns with negative contribution margin ($\text{contribution} < 0$) to positive-contribution campaigns, capped at a $50\%$ (`cap = 0.50`) budget increase per campaign.
* **Data Model Discrepancy**: A schema scale mismatch exists between tables: `campaigns.margin` is stored as a decimal fraction (e.g., $0.42$ for $42\%$), whereas `inventory.net_margin` is stored as a percentage (e.g., $38.5$ for $38.5\%$). Unnormalized joins between these tables cause scale corruption.
* **Funnel Metric Deficit**: `campaign_daily` stores only `spend` and `revenue`. Standard impression-to-conversion funnel metrics—including Click-Through Rate (CTR), Cost Per Click (CPC), and Conversion Rate (CVR)—are absent from the current database structure and cannot be computed without schema expansion.
* **Decision Rule Static Guardrails**: System recommendations rely on hardcoded static parameters: $ROAS\_FLOOR = 1.5$, $LOW\_STOCK = 30\text{ units}$, and $cut\_share = 0.30$.

## 2. Metric Definitions

* **Return on Ad Spend (ROAS)**: The ratio of gross ad-attributed revenue generated per unit of advertising spend.
* **Return on Investment (ROI)**: Net profitability of advertising relative to total cost, incorporating product margin/cost of goods sold (COGS) and ad spend.
* **Customer Acquisition Cost (CAC) / Cost Per Acquisition (CPA)**: The direct advertising cost incurred to generate a single conversion event or purchase.
* **Click-Through Rate (CTR)**: The proportion of ad impressions that resulted in an ad click.
* **Conversion Rate (CVR)**: The percentage of ad clicks or session visits that yielded a completed transaction.
* **Contribution Margin (CM)**: Net revenue generated by ad campaigns after deducting variable product costs (via product margin) and direct advertising expenditures.
* **Days of Inventory Remaining (DIR)**: The projected number of days until an inventory SKU is depleted based on current daily sales velocity.
* **Stockout Risk Probability**: The statistical likelihood that current stock levels drop to zero within the supplier replenishment lead time.

## 3. Recommended Formulas

### Return on Ad Spend (ROAS)

$$ROAS = \frac{\text{Revenue}}{\text{Spend}}$$


*Athena Code Implementation*:


$$\text{safe\_roas}(\text{Revenue}, \text{Spend}) = \begin{cases} \text{round}\left(\frac{\text{Revenue}}{\text{Spend}}, 2\right) & \text{if } \text{Spend} > 0 \\ 0.0 & \text{if } \text{Spend} = 0 \end{cases}$$

### Return on Investment (ROI)

$$ROI = \frac{(\text{Revenue} \times \text{Margin}) - \text{Spend}}{\text{Spend}} = (ROAS \times \text{Margin}) - 1$$

### Contribution Margin Dollar ($CM_$) & Contribution Margin Ratio ($CM_\%$)

$$CM_\$ = \sum_{i} (\text{Revenue}_i \times \text{Margin}_i) - \text{Spend}_i$$

$$CM_\% = \frac{CM_\$}{\text{Revenue}}$$

### Cost Per Acquisition (CPA) / CAC

$$CPA = \frac{\text{Spend}}{\text{Conversions}}$$

### Click-Through Rate (CTR) & Conversion Rate (CVR)

$$CTR = \frac{\text{Clicks}}{\text{Impressions}}, \quad CVR = \frac{\text{Conversions}}{\text{Clicks}}$$

### Days of Inventory Remaining (DIR) & Inventory Sales Velocity ($v$)

$$v = \frac{1}{k} \sum_{t=1}^{k} \left(\frac{\text{Daily Revenue}_t}{ASP}\right)$$

$$DIR = \frac{\text{Stock Level}}{v}$$

### Campaign Reallocation Profitability Rate ($\alpha_c$)

$$\alpha_c = \frac{CM_{\$, c}}{\text{Spend}_c} = \frac{\text{Revenue}_c \times \text{Margin}_c - \text{Spend}_c}{\text{Spend}_c}$$

## 4. Prediction Methodologies

```
+-----------------------------------------------------------------------------------+
|                            PREDICTION METHODOLOGIES                               |
+--------------------------+--------------------------------------------------------+
| 1. REVENUE FORECASTING   | Inputs: Historical daily revenue (30d/90d), spend      |
|                          | Method: Ordinary Least Squares (OLS) Linear Regression |
|                          | Output: 7-day projected revenue sum + confidence band  |
+--------------------------+--------------------------------------------------------+
| 2. INVENTORY FORECASTING | Inputs: Current stock level, daily unit velocity, ASP  |
|                          | Method: Deterministic Run-Rate & Poisson Simulation    |
|                          | Output: Days of Supply Remaining (DIR), stockout date  |
+--------------------------+--------------------------------------------------------+
| 3. EXPENSE IMPACT        | Inputs: Proposed ad spend delta, margin, elasticity    |
|                          | Method: Logarithmic Diminishing Returns Response Curve |
|                          | Output: Expected net change in contribution dollars    |
+--------------------------+--------------------------------------------------------+
| 4. AD SPEND SCENARIO     | Inputs: Budget pool, campaign efficiency, inventory    |
|                          | Method: Bounded Constrained Optimization (Knapsack)    |
|                          | Output: Optimized spend array & projected profit gain  |
+--------------------------+--------------------------------------------------------+

```

### 1. Revenue Forecasting (Time-Series Trend)

* **INPUTS**: Daily aggregated revenue $y_t$ over lookback window $n = 30\text{ days}$, forecast horizon $h = 7\text{ days}$.
* **METHOD**: Ordinary Least Squares (OLS) Linear Regression on temporal index $t \in \{0, 1, \dots, n-1\}$.

$$\bar{t} = \frac{n-1}{2}, \quad \bar{y} = \frac{1}{n} \sum_{t=0}^{n-1} y_t$$


$$\text{Slope } (\beta_1) = \frac{\sum_{t=0}^{n-1} (t - \bar{t})(y_t - \bar{y})}{\sum_{t=0}^{n-1} (t - \bar{t})^2}, \quad \text{Intercept } (\beta_0) = \bar{y} - \beta_1 \bar{t}$$


$$\hat{Y}_{\text{next } 7\text{ days}} = \sum_{i=0}^{6} (\beta_0 + \beta_1(n + i))$$


* **OUTPUT**: Point estimate of total projected revenue over the next 7 days, along with percentage delta compared to the prior 7-day period.
* **ASSUMPTIONS**: Revenue exhibits a linear trend over the 30-day window; ad spend stays relatively stable; no external seasonality shocks occur during the forecast period.
* **LIMITATIONS**: Simple linear regression cannot model intra-week seasonality (e.g., weekend dips) or non-linear decay; highly sensitive to single-day revenue outliers.

### 2. Inventory Scenario Forecasting (Stockout Risk & Run-Rate)

* **INPUTS**: Current stock level $S_0$, campaign revenue daily array $R_t$, Average Selling Price ($ASP$), replenishment lead time $L\text{ (days)}$.
* **METHOD**: Daily Depletion Rate calculation combined with Poisson demand simulation for stockout probability.

$$\text{Daily Unit Velocity } (v) = \frac{\frac{1}{k}\sum_{t=1}^{k} R_t}{ASP}$$


$$\text{Projected Stock at Day } t: \hat{S}_t = \max(0, S_0 - v \cdot t)$$


$$\text{Stockout Threshold Index}: \mathbb{P}(\text{Stockout within } L \text{ days}) = \mathbb{P}(\text{Demand}_{L} > S_0)$$


* **OUTPUT**: Projected Days of Supply Remaining ($DIR = \lfloor \frac{S_0}{v} \rfloor$), stockout date prediction, and stockout warning triggers.
* **ASSUMPTIONS**: Sales velocity maps directly from campaign revenue; unit price $ASP$ remains constant; supplier lead time $L$ is fixed.
* **LIMITATIONS**: Fails to account for order cancellations, batch promotional surges, or shared multi-SKU inventory allocation.

### 3. Expense Impact & Marginal ROI Scenario Analysis

* **INPUTS**: Baseline spend $S_0$, proposed spend change $\Delta S$, channel elasticity exponent $\beta \in (0, 1]$, product margin $m$.
* **METHOD**: Logarithmic Diminishing Returns Yield Curve modeling.

$$\text{Projected Revenue } R(S) = \alpha \cdot S^\beta$$


$$\Delta R = R(S_0 + \Delta S) - R(S_0)$$


$$\Delta CM = (\Delta R \times m) - \Delta S$$


* **OUTPUT**: Marginal revenue projection $\Delta R$ and net contribution profit impact $\Delta CM$.
* **ASSUMPTIONS**: Ad spend scaling encounters diminishing marginal returns ($\beta < 1$) due to audience saturation and auction competition.
* **LIMITATIONS**: Parameter $\beta$ must be estimated per channel using historical spend variance; uncalibrated elasticity risks underestimating ad decay.

### 4. Advertising Spend Scenario Optimization

* **INPUTS**: Target budget pool $B$, current campaign spends $s_c$, campaign profitability rates $\alpha_c = \frac{CM_c}{\text{Spend}_c}$, stock constraints $I_c$.
* **METHOD**: Bounded Reallocation Optimization.

$$\text{Cut Pool } P = \sum_{c \in \text{Losers}} (s_c \times 0.30) \quad \text{where } \text{Losers} = \{c \mid CM_c < 0\}$$


$$\text{Winner Weight } w_c = \frac{\alpha_c}{\sum_{j \in \text{Winners}} \alpha_j} \quad \text{where } \text{Winners} = \{c \mid CM_c > 0\}$$


$$\Delta s_c = \min\left(P \times w_c, \, s_c \times 0.50\right)$$


* **OUTPUT**: Campaign-level recommended spend array $s_c^{\text{rec}} = s_c + \Delta s_c$, expected overall contribution gain $\Delta CM_{\text{total}}$.
* **ASSUMPTIONS**: Spend reallocations yield marginal returns equal to historical average profitability rates $\alpha_c$ within the bounded window.
* **LIMITATIONS**: The static model in `app.py` assumes constant linear efficiency across spend shifts, ignoring auction price increases at higher budgets.

## 5. Decision Methodology

Athena evaluates campaigns against 4 operational status states: **SCALE**, **HOLD**, **REDUCE**, and **PAUSE**.

```
+---------------------------------------------------------------------------------------+
|                               ATHENA DECISION MATRIX                                  |
+--------+-----------------------+--------------------+---------------------------------+
| STATUS | PRIMARY CONDITION     | INVENTORY STATE    | ACTION EXECUTED                 |
+--------+-----------------------+--------------------+---------------------------------+
| SCALE  | ROAS >= 1.5, CM$ > 0  | Stock > 30 units   | Increase daily spend (+10-20%)  |
| HOLD   | 1.2 <= ROAS < 1.5     | 15 <= Stock <= 30  | Freeze spend; retain current bid|
| REDUCE | ROAS < 1.2, CM$ < 0   | Stock < 15 units   | Decrease daily spend (-20-30%)  |
| PAUSE  | ROAS < 0.8 or Out-of- | Stock = 0 units    | Terminate spend immediately (0) |
|        | Stock (0 units)       |                    |                                 |
+--------+-----------------------+--------------------+---------------------------------+

```

### Quantitative Rules Table

| Decision State | Trigger Rules & Thresholds | Analytical Variables Considered | Mathematical Expression | Operational System Action |
| --- | --- | --- | --- | --- |
| **SCALE** | High ROAS ($\ge 1.5$), Positive CM, Healthy Inventory ($> 30\text{ units}$), Upward Trend | ROAS, Margin, Stock Level, Revenue Slope ($\beta_1$) | $ROAS \ge 1.5 \land CM_\$ > 0 \land S > 30 \land \beta_1 \ge 0$ | Increase daily campaign budget by $+10\%$ to $+20\%$. |
| **HOLD** | Moderate ROAS ($1.2 \le ROAS < 1.5$) OR Inventory warning ($15 \le S \le 30$) | ROAS Floor, Inventory Buffer | $(1.2 \le ROAS < 1.5) \lor (15 \le S \le 30)$ | Maintain budget; prevent automated scaling until stock reorders arrive. |
| **REDUCE** | Low ROAS ($< 1.2$), Negative CM, Critical Low Stock ($< 15\text{ units}$) | Negative Contribution Margin, Stockout Danger | $CM_\$ < 0 \lor (S < 15 \land ROAS \ge 1.5)$ | Cut ad spend by $-20\%$ to $-30\%$ to restrict financial loss or preserve inventory. |
| **PAUSE** | Severe ROAS collapse ($< 0.8$) OR Complete Stockout ($S = 0$) | Zero Inventory, Unprofitable Ad Wasted Spend | $S = 0 \lor (ROAS < 0.8 \land \text{Spend} > 0)$ | Immediately halt ad spend to prevent wasted ad clicks. |

### Decision Variable Rationale

* **ROAS**: Measures immediate ad efficiency. Falling below $ROAS\_FLOOR = 1.5$ indicates ineffective targeting or creative fatigue.
* **Margin ($m$)**: Determines bottom-line profit. A high ROAS on a thin-margin product ($m < 15\%$) can still produce negative net contribution profit.
* **Inventory Level ($S$)**: Prevents advertising products that are low or out of stock. Advertising depleted stock wastes budget on unfulfillable demand.
* **Trend ($\beta_1$)**: Evaluates performance trajectory over 30 days. A declining slope warns that historical average ROAS overstates upcoming performance.
* **Conversion (CVR)**: Pinpoints conversion friction. High CTR with low CVR indicates landing page or pricing issues, whereas low CTR indicates creative fatigue.
* **Forecast ($\hat{Y}$)**: Provides proactive forward-looking spend adjustments rather than relying solely on lagged historical performance.
* **Cost / Spend ($S$)**: Establishes statistical significance thresholds before triggering automated pauses, avoiding premature stops on newly launched campaigns.

## 7. Table-by-Table Database Assessment

### 1. Table: `campaigns`

* **Representation**: Registry of advertising campaigns storing channel assignments and baseline product margins.
* **Analytically Useful Fields**: `campaign_id` (PK), `name`, `channel`, `margin` (stored as decimal float, e.g., $0.42$).
* **Possible Transformations**: Margin conversion to percentage ($0.42 \times 100 = 42\%$), channel-level grouping.
* **Possible Joins**:
* `campaigns.campaign_id = campaign_daily.campaign_id` (1-to-Many): Standard join to calculate campaign spend, revenue, and contribution profit.
* `campaigns.campaign_id = inventory.campaign_id` (1-to-Many): Links campaigns to advertised SKUs.


* **Dangerous / Invalid Joins**: Joining `campaigns` directly with `inventory` without aggregating can duplicate daily spend rows if multiple SKUs map to a single campaign ID.
* **Limitations**: Static margin field does not account for SKU-level margin variations or changing cost structures over time.
* **Appropriate Metrics**: Channel Spend Share, Weighted Channel Margin.
* **Appropriate Visualizations**: Donut Chart (Spend Share by Channel), Horizontal Bar Chart (Channel Contribution).

### 2. Table: `campaign_daily`

* **Representation**: Time-series log of daily ad spend and attributed top-line revenue per campaign.
* **Analytically Useful Fields**: `day` (ISO Date string), `campaign_id` (FK), `spend` (REAL), `revenue` (REAL).
* **Possible Transformations**: Time-window aggregation (`7d`, `30d`, `qtd`), 7-day moving averages, linear trend fitting, period-over-period percentage delta ($\% \Delta$).
* **Possible Joins**: `campaign_daily.campaign_id = campaigns.campaign_id` (Many-to-1): Attaches campaign metadata and margin.
* **Dangerous / Invalid Joins**: Unaggregated joins with `inventory` on `campaign_id` duplicate daily performance rows when multiple SKUs map to one campaign.
* **Limitations**: Missing funnel metrics (`impressions`, `clicks`, `conversions`). CTR, CPC, and CVR cannot be computed.
* **Appropriate Metrics**: Daily ROAS, Total Revenue, Total Spend, Contribution Profit ($R \cdot m - S$), 7-Day Revenue Trend Slope ($\beta_1$).
* **Appropriate Visualizations**: Dual-Axis Line Chart (Revenue vs. Spend over Time), Stacked Area Chart (Revenue Contribution by Campaign).

### 3. Table: `inventory`

* **Representation**: Operational stock tracking table recording product quantities, unit margins, statuses, and campaign linkages.
* **Analytically Useful Fields**: `sku_id` (PK), `product_name`, `stock_level` (INTEGER), `net_margin` (REAL, stored as percentage, e.g., $38.5$), `status` ('SCALE'/'HOLD'/'PAUSE'), `campaign_id` (FK, Nullable).
* **Possible Transformations**: Percentage-to-decimal conversion (`net_margin / 100.0`), stock level status bucketing ($S < 30 \implies \text{LOW\_STOCK}$).
* **Possible Joins**: `inventory.campaign_id = campaigns.campaign_id` (Many-to-1): Maps stock availability to ad campaigns.
* **Dangerous / Invalid Joins**: Direct unaggregated joins with `campaign_daily`. Computing minimum stock per campaign requires explicit aggregation (`MIN(stock_level) GROUP BY campaign_id`). Additionally, multiplying revenue by `inventory.net_margin` instead of `net_margin / 100` results in a $100\times$ calculation error.
* **Limitations**: Snapshot view only; lacks historical stock logs, reorder lead times, supplier MOQ, or COGS.
* **Appropriate Metrics**: Total Stock Quantity, Low-Stock SKU Count ($S < 30$), Days of Inventory Remaining (DIR).
* **Appropriate Visualizations**: Progress Bar / Gauge Chart (Stock Level vs. Low Stock Threshold of 30), Status Badge Matrix Table.

### 4. Table: `alerts`

* **Representation**: Log of active automated performance warnings and critical stock triggers.
* **Analytically Useful Fields**: `id` (PK), `type` ('CRITICAL'/'WARNING'), `code` (Unique Key), `description`, `stats`, `overridden` (INTEGER 0/1).
* **Possible Transformations**: Filtering active vs. overridden alerts (`WHERE overridden = 0`), grouping by severity `type`.
* **Possible Joins**: String extraction on `code` to parse `campaign_id` (e.g., `'CMP001'`).
* **Dangerous / Invalid Joins**: Joining directly on `code` against `campaigns.campaign_id` without string parsing, as `code` contains descriptive text prefixes.
* **Limitations**: Lacks timestamps for alert creation/resolution, preventing alert duration or resolution tracking.
* **Appropriate Metrics**: Unresolved Alert Count, Override Rate.
* **Appropriate Visualizations**: Alert Feed List with Visual Status Indicators (Red for CRITICAL, Amber for WARNING), Interactive Override Toggles.

### 5. Table: `audit_log`

* **Representation**: System activity trail logging data refreshes, alert overrides, and status modifications.
* **Analytically Useful Fields**: `id` (PK), `ts` (ISO Timestamp string), `action` (TEXT), `detail` (TEXT).
* **Possible Transformations**: Action type filtering, chronological sorting.
* **Possible Joins**: Text pattern matching on `detail` to extract associated entities.
* **Dangerous / Invalid Joins**: Direct relational joins without explicit text parsing.
* **Limitations**: Missing user identity fields (`user_id`), preventing multi-user attribution.
* **Appropriate Metrics**: Total System Event Volume, Daily Manual Override Frequency.
* **Appropriate Visualizations**: Audit Feed Table with Time Formatting.

## 10. Claims Athena Should NOT Make

1. **Athena MUST NOT Claim Direct Causal Attribution Without Incrementality Testing**: Correlation between daily ad spend and revenue in `campaign_daily` does not establish causality. Claiming ad spend *caused* $100\%$ of attributed revenue ignores baseline organic sales and multi-channel overlap.
2. **Athena MUST NOT Claim Exact Stockout Dates**: Inventory depletion is probabilistic. Assuming fixed daily unit velocity ignores demand variance, promotional surges, or supply chain shipment delays.
3. **Athena MUST NOT Claim Guaranteed Revenue Gains from Budget Reallocation**: The `/api/optimize` model assumes linear returns on ad spend ($\text{rate} = \frac{CM}{\text{Spend}}$). In practice, scaling ad spend incurs diminishing marginal returns and rising auction CPMs.
4. **Athena MUST NOT Claim User-Level Multi-Touch Attribution**: The underlying database lacks user tracking IDs, click paths, or view-through log data.
5. **Athena MUST NOT Claim Real-Time Automated Ad Network Execution**: Athena operates on local SQLite data and batch CSV imports; it does not feature direct, automated ad network API execution capabilities.

## 11. Important Limitations

1. **Missing Funnel Metrics**: `campaign_daily` records only total daily spend and revenue. Click-Through Rate (CTR), Cost Per Click (CPC), and Conversion Rate (CVR) cannot be derived without schema expansion.
2. **Margin Metric Scale Mismatch**: `campaigns.margin` is stored as a decimal fraction ($0.42$), whereas `inventory.net_margin` is stored as a percentage ($38.5$). Unnormalized joins introduce scale calculation errors.
3. **Linearity Assumption in Budget Reallocation**: The spend optimizer in `/api/optimize` assumes constant linear returns when reallocating budget, ignoring diminishing marginal returns at higher spend levels.
4. **Snapshot-Only Inventory Data**: `inventory` records only the current stock snapshot (`stock_level`). Lacking historical inventory logs, Athena cannot backtest prior stockout events or model seasonal inventory variance.
5. **Lack of Multi-Currency & Lead Time Tracking**: The system assumes unified currency representation without conversion parameters, and assumes instantaneous or unrecorded supplier lead times.
